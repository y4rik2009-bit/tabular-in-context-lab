# Как устроен эксперимент

## Идея статьи

В обычном машинном обучении на каждой новой таблице мы заново подбираем веса модели. **In-context learning** предлагает другой путь: заранее обучить сеть на множестве разных задач, а при встрече с новой таблицей передать ей несколько строк с известными ответами и строки, для которых нужен прогноз. Веса сети при этом уже не обновляются.

Этот проект вдохновлён статьёй [Qu и соавторов, *TabICL*, ICML 2025](https://proceedings.mlr.press/v267/qu25d.html). Авторы создали гораздо более крупную модель и обучали её по сложной программе на огромном количестве синтетических таблиц. Здесь написана **самостоятельная компактная учебная реализация** центрального принципа. Она не использует их библиотеку или веса и не претендует на воспроизведение результатов статьи.

## Что именно реализовано

1. **Генератор задач** в `prior.py` создаёт новые таблицы бинарной классификации. Граница между классами бывает линейной, с взаимодействием признаков, радиальной или периодической. Меняются число признаков, их сочетания, степень шума, порядок столбцов и обозначение классов.
2. **Внимание внутри столбца** в `miniicl.py` сравнивает значения одного признака у разных строк. В каждой строке признак сохраняет свой идентификатор, иначе модель не сможет сопоставить его с тем же признаком в другой строке.
3. **Внимание внутри строки** объединяет признаки в представление строки. Специальный CLS-токен собирает информацию.
4. **Внимание между строками** получает обучающие строки вместе с метками классов и строки-запросы со скрытой меткой. Маска запрещает обучающим строкам читать запросы, а каждому запросу — читать другие запросы.
5. **Локальное внимание по расстоянию** дополнительно сопоставляет запрос с известными примерами в нормализованном пространстве признаков. Температура и вес этого пути обучаются вместе с Transformer. Это явно добавленная мной индуктивная подсказка для маленького обучения на CPU, а не компонент оригинальной TabICL. Итоговый logit — сумма глобальной поправки Transformer и локального прогноза. Ни одна настоящая метка тестовой строки не передаётся сети.
6. На стадии `train.py` сеть видит только искусственные задачи. На стадии `benchmark.py` готовые веса фиксированы. Никакого градиентного обучения на реальных наборах нет.

Это три стадии обработки, **вдохновлённые** TabICL. Размер сети, генератор данных, маски внимания, оптимизация и режим проверки здесь собственные и намного меньше авторских. В частности, используем фиксированные позиции признаков внутри одной таблицы; произвольная перестановка столбцов *после* обучения может изменить прогноз. Перед обучением порядок признаков в искусственных задачах случайно меняется для устойчивости. Перестановка строк контекста не меняет смысл задачи; это проверено тестом.

## Данные и проверка

Реальные бинарные наборы из UCI: [Banknote Authentication](https://archive.ics.uci.edu/dataset/267/banknote+authentication), [Breast Cancer Wisconsin Original](https://archive.ics.uci.edu/dataset/15/breast+cancer+wisconsin+original), [Ionosphere](https://archive.ics.uci.edu/dataset/52/ionosphere). Их страницы указывают лицензию CC BY 4.0. Данные скачиваются при первом запуске и сохраняются только локально в `.cache/data/`; исходные таблицы на GitHub не загружаются.

Для каждого из трёх случайных чисел генератора 75% строк образуют обучающий пул, 25% — тестовый. Из пула выбираются ровно 32 строки с известными метками: **все модели получают те же 32 строки**. Остальные строки пула не используются. Оцениваются до 100 тестовых строк. Импутация, отбор максимум 10 признаков и масштабирование обучаются только на 32 строках контекста. Большая размерность Ionosphere поэтому сводится к 10 признакам с помощью F-теста; это ограничение компактной модели.

Сравнения:

- `MiniTabICL`: фиксированная сеть, которая читает 32 примера в контексте.
- `MiniTabICL, random weights`: та же архитектура со случайными весами. Проверяет, помогает ли предварительное обучение сверх встроенного локального внимания.
- `MiniTabICL, shuffled context labels`: те же признаки и то же число классов, но метки перемешаны между строками. Это проверка использования *связи* между объектом и его меткой.
- Logistic Regression: обучается с нуля на 32 строках.
- 5-NN: пять ближайших известных строк, взвешенных по расстоянию.
- CatBoost: 300 деревьев глубины 4, также обучается с нуля на 32 строках.

Метрики: ROC AUC и accuracy (больше лучше), log loss и Brier score (меньше лучше). Последние две оценивают качество вероятностей, а не только выбранный класс. Время включает прогноз для MiniTabICL и обучение плюс прогноз для базовых моделей; поэтому сравнение времени имеет разный смысл и явно маркируется.

## Ограничения

- Это небольшое исследование на трёх наборах и трёх разбиениях, не рейтинг всех методов классификации.
- Синтетический генератор куда проще обучающей смеси оригинальной TabICL. Слабый результат не опровергает статью; сильный не доказывает превосходства над официальной моделью.
- Здесь только числовые признаки и бинарные ответы; категориальные столбцы, задачи с несколькими классами и пропущенные значения обрабатываются упрощённо.
- Отбор признаков по 32 строкам может быть нестабилен. Он одинаков для всех моделей в сравнении.
- Загрузка модели через `torch.load` предназначена только для собственных доверенных файлов, созданных этим же проектом.
